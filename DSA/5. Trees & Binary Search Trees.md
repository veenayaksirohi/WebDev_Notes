## 📝 Overview

Trees are hierarchical, non-linear data structures used widely in algorithms and systems (parsing, filesystems, indexing). Binary Search Trees (BSTs) are binary trees with an ordering property that supports efficient search, insert, and delete.

This note gives definitions, traversal algorithms, BST operations, common interview problems (height, diameter, LCA), and a brief intro to balanced trees.

---

## 🌳 Tree Basics

### Terminology

* **Node**: element containing value and children pointers.
* **Root**: top node (no parent).
* **Leaf**: node with no children.
* **Internal node**: non-leaf node.
* **Edge**: connection between parent and child.
* **Height of node**: longest path to a leaf from that node.
* **Depth of node**: distance from root to that node.
* **Level**: set of nodes with the same depth.

### Representation (nodes, pointers/arrays)

Common node structure (binary tree):

```python
class Node:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None
```

Trees can also be stored in arrays (binary heap style) where `left = 2*i+1`, `right = 2*i+2` — useful for complete trees.

## 🔁 Traversals

### Preorder / Inorder / Postorder (recursive & iterative)

* **Preorder**: `root -> left -> right`
* **Inorder**: `left -> root -> right` (in BSTs yields sorted order)
* **Postorder**: `left -> right -> root`

**Recursive Inorder**

```python
def inorder(node):
    if not node: return
    inorder(node.left)
    print(node.val)
    inorder(node.right)
```

**Iterative Inorder (stack)**

```python
stack, cur = [], root
while stack or cur:
    while cur:
        stack.append(cur)
        cur = cur.left
    cur = stack.pop()
    print(cur.val)
    cur = cur.right
```

### Level-order (BFS)

Use a queue to visit nodes level by level.

```python
from collections import deque
q = deque([root])
while q:
    node = q.popleft()
    print(node.val)
    if node.left: q.append(node.left)
    if node.right: q.append(node.right)
```

## 🔎 Binary Search Trees (BST)

### BST property & invariants

For any node `n`: all values in `n.left` < `n.val` < all values in `n.right` (assuming no duplicates; duplicates handled by policy: left or right consistently).

Implications:

* Inorder traversal returns sorted sequence
* Search/insert/delete average `O(h)` where `h` is tree height

### Insert / Search / Delete (examples)

**Search**

```python
def bst_search(root, key):
    while root:
        if key == root.val: return root
        root = root.left if key < root.val else root.right
    return None
```

**Insert (iterative)**

```python
def bst_insert(root, key):
    if not root: return Node(key)
    cur = root
    while True:
        if key < cur.val:
            if cur.left: cur = cur.left
            else:
                cur.left = Node(key)
                break
        else:
            if cur.right: cur = cur.right
            else:
                cur.right = Node(key)
                break
    return root
```

**Delete (three cases)**

1. Node is leaf — remove it.
2. Node has one child — replace node with child.
3. Node has two children — replace with inorder successor (min in right subtree) or predecessor, then delete successor.

```python
def delete_node(root, key):
    if not root: return None
    if key < root.val:
        root.left = delete_node(root.left, key)
    elif key > root.val:
        root.right = delete_node(root.right, key)
    else:
        # found
        if not root.left: return root.right
        if not root.right: return root.left
        # two children
        succ = root.right
        while succ.left: succ = succ.left
        root.val = succ.val
        root.right = delete_node(root.right, succ.val)
    return root
```

## 🧠 Common Problems & Patterns

### Height / Depth

Compute tree height (max depth) via DFS recursion.

```python
def height(node):
    if not node: return 0
    return 1 + max(height(node.left), height(node.right))
```

### Diameter of a tree

Longest path between any two nodes (in edges or nodes). Efficient approach computes height and diameter in single DFS (O(n)).

```python
# returns (height, diameter)
def height_diameter(node):
    if not node: return (0, 0)
    lh, ld = height_diameter(node.left)
    rh, rd = height_diameter(node.right)
    h = 1 + max(lh, rh)
    diam = max(lh + rh, ld, rd)  # path through root = lh+rh
    return (h, diam)
```

### Tree views (left/right/top/bottom)

* **Left view**: first node visible at each level from left side — BFS level-order + pick first per level
* **Right view**: pick last node per level
* **Top / Bottom view**: use horizontal distance map (HD from root; BFS + map HD→node)

### Lowest Common Ancestor (LCA)

* **BST LCA**: use BST property: if both keys < node.val → go left; both > → go right; else node is LCA.

```python
def lca_bst(root, a, b):
    while root:
        if a < root.val and b < root.val: root = root.left
        elif a > root.val and b > root.val: root = root.right
        else: return root
```

* **Binary Tree LCA** (no ordering): recursive check `left = recurse(left)`, `right = recurse(right)`, if both non-null current node is LCA.

### Balanced trees intro (AVL / Red-Black)

* **Problem:** naive BST can degrade to linked list (`O(n)` ops) if unbalanced.
* **AVL tree:** height-balanced; rotations (LL, RR, LR, RL) maintain `O(log n)` height. Stricter balancing than RB.
* **Red-Black tree:** looser balancing guarantee; faster inserts/deletes amortized; used by many std libraries (e.g., C++ `std::map` historically, Java `TreeMap`).

Key idea: keep tree height `O(log n)` via rotations and color/balance rules.

## ✅ Complexity Summary

* Traversals (any): `O(n)` time, `O(h)` recursion stack (or `O(n)` worst)
* BST average operations: `O(h)` where `h`≈`log n` if balanced; worst `O(n)` if skewed
* Height/diameter/LCA (binary tree): `O(n)` time, `O(h)` space

---

## ✅ Best Practices

* Use iterative traversals for very deep trees to avoid recursion limits, or increase recursion depth carefully
* For LCA in many queries, preprocess using parent/ancestor binary lifting or Euler Tour + RMQ (range minimum query)
* Prefer balanced trees (AVL/RB) or use library implementations unless asked to implement
* Validate null and edge cases (single node, empty tree)

---

## ⚠️ Common Pitfalls

* Assuming BST remains balanced after arbitrary inserts
* Off-by-one in level-order/height definitions (nodes vs edges)
* Forgetting to update parent pointers if you maintain them
* Using recursion on extremely deep (skewed) trees without considering stack limits
