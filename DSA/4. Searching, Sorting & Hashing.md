## 🔎 Searching

### Linear Search

* Scan each element until found. Works on unsorted arrays.
* Time: `O(n)`; Space: `O(1)`

**Simple code**

```python
def linear_search(arr, target):
    for i, x in enumerate(arr):
        if x == target:
            return i
    return -1
```

### Binary Search

* Requires sorted array. Repeatedly halve search space.
* Time: `O(log n)`; Space: `O(1)` (iterative) or `O(log n)` (recursive stack)

**Template (iterative)**

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr)-1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target: return mid
        if arr[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1
```

### Search-on-answers (Binary search on answer space)

* Use when the answer is numeric and monotonic wrt a predicate.
* Example: minimum maximum subarray sum for k partitions, minimize capacity to ship packages within D days.

**Pattern**

1. Define predicate `ok(x)` that returns True if `x` feasible
2. Binary-search on range of possible `x` values

```python
lo, hi = lower_bound, upper_bound
while lo < hi:
    mid = (lo + hi) // 2
    if ok(mid): hi = mid
    else: lo = mid + 1
return lo
```

## 📚 Sorting Algorithms

| Algorithm  | Time (avg) | Time (worst) |        Space |           Stable           |
| ---------- | ---------: | -----------: | -----------: | :------------------------: |
| Bubble     |     O(n^2) |       O(n^2) |         O(1) |             Yes            |
| Insertion  |     O(n^2) |       O(n^2) |         O(1) |             Yes            |
| Selection  |     O(n^2) |       O(n^2) |         O(1) |             No             |
| Merge Sort | O(n log n) |   O(n log n) |         O(n) |             Yes            |
| Quick Sort | O(n log n) |       O(n^2) | O(log n) avg | No (unless stable variant) |
| Heap Sort  | O(n log n) |   O(n log n) |         O(1) |             No             |
| Counting   |   O(n + k) |     O(n + k) |         O(k) |             Yes            |
| Radix      |   O(n * d) |     O(n * d) |     O(n + k) |      Yes (LSD stable)      |

### Bubble / Insertion / Selection

* Simple, useful for tiny arrays and teaching. Insertion is good for nearly-sorted data.

### Merge Sort

* Divide array into halves, sort, and merge. Stable and predictable `O(n log n)`.
* Good for linked-lists (no extra array copying required).

### Quick Sort

* Pick pivot (first/random/median-of-three). Partition and recurse.
* Average `O(n log n)`, worst `O(n^2)` for bad pivots (use random pivot to avoid worst-case in practice).

**Partition (Lomuto sketch)**

```python
pivot = arr[hi]
i = lo
for j in range(lo, hi):
    if arr[j] < pivot:
        arr[i], arr[j] = arr[j], arr[i]
        i += 1
arr[i], arr[hi] = arr[hi], arr[i]
```

### Counting / Radix / Bucket

* Non-comparison sorts for integers or bounded keys.
* Counting sort `O(n + k)`, Radix sorts digits `O(n * d)`.

### When to use which sort

* Use built-in sorts (`Timsort` in Python) for general purpose (stable, optimized)
* Merge sort when stability required and memory OK
* Quick sort for in-place performance (but randomized pivot)
* Counting/radix when key range small / integers

## 🎯 Order Statistics (k-th element)

### Quickselect (Hoare/Quickselect)

* Average `O(n)`, worst `O(n^2)`; like quicksort but recurse only one side.

```python
def quickselect(arr, k): # 0-based k
    lo, hi = 0, len(arr)-1
    while True:
        p = partition(arr, lo, hi)
        if p == k: return arr[p]
        if k < p: hi = p-1
        else: lo = p+1
```

### Heap-based approach

* Use a max-heap of size `k` for k-th smallest: `O(n log k)` time, `O(k)` space.
* Use a min-heap and pop `k-1` times for k-th smallest: `O(n + k log n)`.

## 🔐 Hashing (Hash Maps & Sets)

### Hash map basics

* Provide average `O(1)` insert/lookup/delete. Backed by arrays + hashing function + collision handling.
* Useful for frequency counts, memoization, grouping, deduplication.

**Common patterns**

* Frequency map: count occurrences → `Counter` or dict
* Two-sum (unsorted): store complements in hashmap
* Sliding window with hashmap for counts

### Collision handling

* **Chaining**: each bucket holds a list/chain of entries (simple, robust)
* **Open addressing**: probe sequence (linear, quadratic, double hashing)

**Load factor**: performance degrades if load factor too high; rehashing/resizing needed.

### Frequency maps & common patterns

* Count occurrences: `for x in arr: freq[x] += 1`
* Group by key: append to list `groups[key].append(item)`
* Detect duplicates: check seen set

## ✅ Best Practices

* Use language built-ins (sorted, heapq, dict) in interviews unless asked to implement
* For binary search, prefer writing predicate-based template when searching for a boundary
* Randomize pivots in quicksort/quickselect to avoid worst-case
* Use Counters/defaultdict for frequency problems
* Choose algorithm by input size and constraints (memory vs speed)

---

## ⚠️ Common Pitfalls

* Off-by-one errors in binary search (inclusive/exclusive boundaries)
* Using quicksort without random pivot on adversarial inputs
* Assuming hash map worst-case `O(1)` — adversarial collisions can degrade to `O(n)`
* Misusing sorting stability when order matters
