## 📝 Overview

A **heap** is a complete binary tree that satisfies the heap property: each parent is ordered with respect to its children (<= for min-heap, >= for max-heap). Heaps are commonly implemented using arrays and are the backbone of **priority queues**, which support fast retrieval of the highest/lowest priority element.

Heaps are used for scheduling, shortest-path algorithms (Dijkstra), streaming top-k queries, and as the basis for heap sort.

---

## 📐 Heap Concepts & Array Representation

### Min-heap vs Max-heap

* **Min-heap:** parent ≤ children — root is minimum.
* **Max-heap:** parent ≥ children — root is maximum.

### Array index mapping (parent/child)

For 0-based arrays:

* `parent(i) = (i - 1) // 2`
* `left(i) = 2*i + 1`
* `right(i) = 2*i + 2`

Example (max-heap array): `[40, 20, 30, 10, 15]` represents a complete binary tree with `40` as root.

## 🛠️ Core Operations

### Insert (sift-up / swim)

1. Add element at end of array.
2. While element <parent (min-heap) swap upward.

```python
# sketch (min-heap)
def push(heap, val):
    heap.append(val)
    i = len(heap)-1
    while i > 0:
        p = (i-1)//2
        if heap[i] < heap[p]:
            heap[i], heap[p] = heap[p], heap[i]
            i = p
        else:
            break
```

**Time:** `O(log n)` per insert.

### Extract / Delete root (sift-down / sink)

1. Replace root with last element, pop last.
2. Sift the new root down by swapping with smaller (min-heap) child until heap property restored.

```python
def pop(heap):
    if not heap: return None
    heap[0], heap[-1] = heap[-1], heap[0]
    val = heap.pop()
    i = 0
    n = len(heap)
    while True:
        l = 2*i + 1; r = 2*i + 2; smallest = i
        if l < n and heap[l] < heap[smallest]: smallest = l
        if r < n and heap[r] < heap[smallest]: smallest = r
        if smallest == i: break
        heap[i], heap[smallest] = heap[smallest], heap[i]
        i = smallest
    return val
```

**Time:** `O(log n)` per extract.

### Heapify (sift-down) & Build-Heap (linear time)

To build a heap from an unsorted array, run `sift-down` from last parent down to root:

```text
for i in reversed(range(n//2)): sift_down(i)
```

This runs in **O(n)** time (not `O(n log n)`) because lower levels have smaller subtree heights.

### Peek / Top

Access root element in `O(1)` without removal.

## 🎯 Priority Queues & Use Cases

Priority queues expose push/pop of highest/lowest priority.

**Use cases:**

* **Dijkstra's algorithm** (min-priority queue keyed by tentative distance)
* **A*** search (open set)
* **Event simulation** (time-ordered events)
* **Task scheduling** (choose highest-priority job)
* **Streaming top-K** maintenance

Implementation notes:

* Use language provided priority queue (`heapq` in Python) but be careful: Python `heapq` is min-heap; for max-heap store negative keys.
* For mutable priorities or decrease-key operations (needed by Dijkstra), either push a new entry and ignore stale ones or use a specialized indexed heap/fibonacci heap (rare in interviews).

## ⚙️ Heap-based Algorithms

### Heap Sort (in-place)

1. Build max-heap from array (`O(n)`).
2. For `i` from `n-1` downto `1`: swap `arr[0]` and `arr[i]`, reduce heap size by 1, sift-down root.

**Complexity:** `O(n log n)` time, `O(1)` extra space (in-place).

**Note:** Heap sort is not stable.

### Top-K elements (heap approaches)

* **Top-K largest (streaming)**: keep a min-heap of size `k`. For each element, if heap size < k push; else if x > heap[0]: pop then push x. Complexity `O(n log k)`.
* **Top-K smallest**: use max-heap of size `k` (or min-heap with negative keys).
* **Using `nlargest`/`nsmallest`** built-ins when allowed.

### K-way merge (merge k sorted lists)

* Use a min-heap of size `k` storing current head of each list; pop min, push next from same list. Complexity `O(N log k)` for total N elements.

---

## ✅ Complexity Summary

* `push`: `O(log n)`
* `pop` (extract min/max): `O(log n)`
* `peek`: `O(1)`
* `build-heap` from array: `O(n)`
* `heap-sort`: `O(n log n)` time, `O(1)` extra space
* `top-k` streaming: `O(n log k)` time, `O(k)` space

---

## ✅ Best Practices

* Use built-in heap implementations for correctness and speed; implement manually when asked.
* For decrease-key (Dijkstra), either push duplicates with updated priority and skip stale entries or use an indexed priority queue.
* Prefer min-heap for generic problems; convert for max-heap by negating keys.
* Use `build-heap` when you have full array rather than inserting one-by-one.

---

## ⚠️ Common Pitfalls

* Forgetting that Python `heapq` is a min-heap (negate for max-heap).
* Not handling duplicate or stale entries when using lazy-deletion for priority updates.
* Expecting heap to support efficient arbitrary deletions/updates—standard binary heap doesn't support O(log n) decrease-key without index mapping.
* Off-by-one in index math for parent/child in array representation.
