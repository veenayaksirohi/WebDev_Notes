## 📝 Overview

Linear data structures (linked lists, stacks, queues) are foundational interview topics. Know their structures, typical operations, complexity, and common patterns (fast–slow pointers, monotonic stacks, circular buffers). These are asked for both implementation and application questions.

## 🔗 Linked Lists

### Singly Linked List (definition & ops)

A singly linked list is a sequence of nodes where each node stores a value and a pointer to the next node.

**Node (conceptual)**

```text
class Node:
  val
  next
```

**Basic operations & complexity**

* Traverse: `O(n)` time, `O(1)` extra space
* Insert at head: `O(1)`
* Insert at tail: `O(1)` if tail pointer maintained, otherwise `O(n)`
* Delete node (given previous): `O(1)`; delete by value: `O(n)` to find it

**Example — reverse a singly linked list (iterative)**

```python
prev = None
cur = head
while cur:
  nxt = cur.next
  cur.next = prev
  prev = cur
  cur = nxt
# prev is new head
```

### Doubly Linked List

Each node has `prev` and `next` pointers. Useful for O(1) deletion when node reference available and for LRU caches.

**Ops**

* Insert/remove at both ends: `O(1)`
* Extra memory per node (two pointers)

### Circular Linked List

Last node points back to head. Useful for round-robin, implementing circular buffers, or elegant rotation.

**Caution:** careful handling of single-node list and termination conditions when traversing.

### Fast–Slow (Tortoise & Hare) tricks

Use two pointers moving at different speeds (slow = 1 step, fast = 2 steps).

**Common uses:**

* Detect cycle: if fast meets slow → cycle exists.
* Find start of cycle: reset one pointer to head, move both at 1 — meeting point is cycle entry.
* Find middle: when fast reaches end, slow is middle.

**Cycle detect (Floyd’s algorithm)**

```python
slow = fast = head
while fast and fast.next:
  slow = slow.next
  fast = fast.next.next
  if slow == fast:
    return True
return False
```

### Common interview problems & snippets

* Reverse linked list (iterative/recursive)
* Find middle node
* Detect & remove cycle
* Merge two sorted lists
* Delete nth node from end (use fast pointer advanced by n)

**Delete nth from end (two-pointer trick)**

```python
fast = slow = dummy = Node(0, head)
for _ in range(n): fast = fast.next
while fast.next:
  fast = fast.next
  slow = slow.next
# slow.next is node to delete
slow.next = slow.next.next
```

## 📚 Stacks

### Array/list-based stack basics

Stack: LIFO (last-in-first-out). Push/pop both `O(1)` amortized for dynamic arrays.

**Use built-in lists in interviews (e.g., Python `list.append` / `pop`)**

**Common stack operations**

* `push(x)`, `pop()`, `peek()` — `O(1)`
* `isEmpty()` — `O(1)`

### Expression evaluation (infix → postfix → evaluate)

Shunting-yard algorithm converts infix expression to postfix using a stack for operators; then evaluate postfix with a value stack.

**Postfix evaluation (sketch)**

```text
for token in tokens:
  if number: push
  else if operator: b=pop(); a=pop(); push(apply(op,a,b))
result = pop()
```

**Useful in interviews:** implement parentheses matching, convert expression forms, compute RPN.

### Monotonic stacks (next greater / next smaller)

Maintain stack in strictly increasing / decreasing order to answer range queries like next greater element in `O(n)` total.

**Next greater element (sketch)**

```python
res = [-1]*n
stack = [] # store indices with decreasing values
for i in range(n):
  while stack and arr[i] > arr[stack[-1]]:
    res[stack.pop()] = arr[i]
  stack.append(i)
```

**Applications:** histogram max area, sliding-window max (deque variant), span problems.

## 🚪 Queues

### Simple queues & circular queues

Queue: FIFO. Implement with linked list or dynamic array with head/tail indices.

**Circular queue idea (array size k)**

* Use `head`, `tail`, and count or leave one slot empty to differentiate full/empty.
* Enqueue: `arr[tail] = x; tail = (tail+1) % k`
* Dequeue: `x = arr[head]; head = (head+1) % k`

**Complexities:** enqueue/dequeue `O(1)`

### Deque (double-ended queue)

Supports push/pop at both ends in `O(1)`. Useful for sliding-window maximum and BFS with 0-1 weights.

**Python:** `collections.deque` supports `popleft()` efficiently.

### Applications: BFS, sliding window

* **BFS** uses queue: discover neighbors, mark visited, enqueue.
* **Sliding window max**: deque stores candidate indices in decreasing order for `O(n)` algorithm.

**Sliding window max sketch**

```python
from collections import deque
dq = deque()
for i in range(n):
  while dq and arr[dq[-1]] <= arr[i]: dq.pop()
  dq.append(i)
  if dq[0] == i-k: dq.popleft()
  if i >= k-1: ans.append(arr[dq[0]])
```

## 🧩 Applications & Use-cases

* **Undo/redo**: use two stacks (undo, redo)
* **Function call stack**: recursion implementation and backtracking
* **BFS / shortest path on unweighted graphs**: queue
* **LRU cache**: doubly linked list + hashmap
* **Expression parsing & calculators**: stacks
* **Job scheduling / round-robin**: circular queues

## ✅ Time & Space Complexity Summary

| Operation / Structure |          Time (avg / worst) | Space |
| --------------------- | --------------------------: | ----: |
| Linked list traversal |                        O(n) |  O(1) |
| Insert at head (LL)   |                        O(1) |  O(1) |
| Insert at tail (LL)   | O(1) if tail kept else O(n) |  O(1) |
| Stack push/pop        |                        O(1) |  O(n) |
| Queue enqueue/dequeue |                        O(1) |  O(n) |

## ✅ Best Practices

* Use built-in data structures when allowed (e.g., `deque`) to avoid reinventing wheels
* Always check edge cases: empty structures, single-element, even/odd lengths
* For linked lists, prefer dummy `head` to simplify edge-case logic
* When asked for O(1) deletion given a node, remember doubly-linked list or previous pointer requirement

---

## ⚠️ Common Pitfalls

* Off-by-one errors with circular buffers
* Forgetting to update `tail` or `prev` pointers on insert/delete
* Using Python lists for queue `pop(0)` (O(n)) instead of `deque`
* Not handling NULL/None nodes when reversing or merging
