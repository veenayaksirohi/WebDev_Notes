## 📝 Overview

This note covers essential graph algorithms for shortest paths, minimum spanning trees, and advanced connectivity analyses. Each algorithm includes purpose, intuition, complexity, and a concise code sketch suitable for interviews.

---

## 🔎 Single-Source Shortest Paths

### Dijkstra (non-negative weights)

**Purpose:** Shortest path from a source to all nodes when edge weights are non-negative.

**Idea:** Greedy: always pick the node with smallest tentative distance (use a min-heap), relax outgoing edges.

**Pseudocode (heap-based):**

```python
import heapq

def dijkstra(graph, src):
    # graph: adj list {u: [(v,w), ...]}
    dist = {v: inf for v in graph}
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d,u = heapq.heappop(pq)
        if d > dist[u]: continue
        for v,w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

**Complexity:** `O((V + E) log V)` with binary heap (or `O(E + V log V)` depending on implementation). Use Fibonacci heap for theoretical `O(E + V log V)`.

**When to use:** non-negative weights, fast in practice.

---

### Bellman–Ford (negative weights & cycle detection)

**Purpose:** Handles graphs with negative edge weights and detects negative cycles reachable from source.

**Idea:** Relax all edges `V-1` times. If any edge relaxes on the `V`-th pass, a negative cycle exists.

**Pseudocode:**

```python
def bellman_ford(edges, V, src):
    dist = [inf]*V; dist[src]=0
    for _ in range(V-1):
        changed = False
        for u,v,w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w; changed = True
        if not changed: break
    # detect negative cycle
    for u,v,w in edges:
        if dist[u] + w < dist[v]:
            return None  # negative cycle reachable
    return dist
```

**Complexity:** `O(V * E)`

**When to use:** when negative weights are present or you need cycle detection.

---

### Comparisons & when to use which

* Use **Dijkstra** for non-negative weights (fast).
* Use **Bellman–Ford** if negative weights or to detect negative cycles.
* If multiple sources or dense graphs, consider different data structures and algorithms (Johnson’s algorithm for all-pairs with negative edges uses Bellman-Ford + Dijkstra).

## 📐 All-Pairs Shortest Paths

### Floyd–Warshall (dynamic programming)

**Purpose:** Compute shortest paths between every pair of nodes (works with negative weights but no negative cycles).

**Idea:** DP over intermediate vertices: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])` for k from 0..V-1.

**Pseudocode:**

```python
# initialize dist matrix with weights or inf
for k in range(V):
    for i in range(V):
        for j in range(V):
            dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```

**Complexity:** `O(V^3)` time, `O(V^2)` space.

**When to use:** small graphs, or when you need distances between all pairs.

## 🌲 Minimum Spanning Tree (MST)

A spanning tree connects all vertices with minimum total edge weight.

### Kruskal's algorithm (edges + DSU)

**Idea:** Sort edges by weight; take edges in order if they connect different components (use union-find to check).

**Pseudocode:**

```python
# edges: list of (w,u,v)
edges.sort()
uf = UnionFind(n)
mst = []
for w,u,v in edges:
    if uf.find(u) != uf.find(v):
        uf.union(u,v); mst.append((u,v,w))
```

**Complexity:** `O(E log E)` for sorting + near-linear union-find.

**When to use:** when edges are easy to sort; works well for sparse graphs.

---

### Prim's algorithm (heap-based)

**Idea:** Grow MST from a start node: pick the cheapest edge crossing the cut using a min-heap of candidate edges (or keyed by node distances similar to Dijkstra).

**Pseudocode (node-keyed):**

```python
import heapq
in_mst = [False]*n
key = [inf]*n; key[src]=0
pq = [(0, src)]
while pq:
    k,u = heapq.heappop(pq)
    if in_mst[u]: continue
    in_mst[u] = True
    for v,w in graph[u]:
        if not in_mst[v] and w < key[v]:
            key[v] = w; heapq.heappush(pq, (w, v))
```

**Complexity:** `O((V + E) log V)` with heap.

**When to use:** dense graphs with adjacency matrix variant, or when constructing from nodes is easier.

## 🔗 Disjoint Set / Union-Find

### Core operations & optimizations

* `find(x)`: returns representative/root of x
* `union(a,b)`: merge sets containing a and b

**Optimizations:** path compression (flatten tree during find) and union by rank/size — together they make operations nearly `O(α(n))` (inverse Ackermann) amortized.

**Sketch:**

```python
def find(x):
    if parent[x]!=x: parent[x] = find(parent[x])
    return parent[x]

def union(a,b):
    ra, rb = find(a), find(b)
    if ra==rb: return False
    if size[ra] < size[rb]: ra,rb = rb,ra
    parent[rb] = ra; size[ra] += size[rb]
    return True
```

### Use cases

* Kruskal's MST, connectivity queries, dynamic connectivity, offline query processing (e.g., union-on-edges), detecting cycles in undirected graphs.

## 🕳️ Bridges & Articulation Points (Tarjan)

### Low-link concept & DFS discovery time

* Run DFS and record `disc[u]` (discovery time) and `low[u]` (lowest discovery time reachable from u through 0+ back-edges).
* **Bridge:** edge `(u,v)` is a bridge if `low[v] > disc[u]` (no back-edge from v-subtree to u or ancestors).
* **Articulation point (AP):** a node whose removal increases number of connected components. Conditions:

  * Root of DFS tree with 2+ children is AP.
  * Non-root u is AP if it has child v with `low[v] >= disc[u]`.

### Code sketch (bridges & articulation points)

```python
# global: time=0
def dfs(u, parent):
    visited[u]=True
    disc[u]=low[u]=time; time+=1
    child_count=0
    for v in graph[u]:
        if not visited[v]:
            child_count+=1
            dfs(v, u)
            low[u]=min(low[u], low[v])
            # bridge
            if low[v] > disc[u]: bridges.append((u,v))
            # articulation
            if parent!=-1 and low[v] >= disc[u]: ap.add(u)
        elif v != parent:
            low[u] = min(low[u], disc[v])
    if parent==-1 and child_count>1: ap.add(u)
```

**Complexity:** `O(V + E)` for single DFS.

---

## ✅ Complexity Summary

* Dijkstra (heap): `O((V + E) log V)`
* Bellman–Ford: `O(V * E)`
* Floyd–Warshall: `O(V^3)`
* Kruskal: `O(E log E)` + DSU
* Prim (heap): `O((V + E) log V)`
* DSU operations: nearly `O(1)` amortized (`O(α(n))`)
* Bridges / AP (Tarjan): `O(V + E)`

---

## ✅ Best Practices

* Choose Dijkstra for non-negative weights; Bellman–Ford if negatives exist.
* Use adjacency lists for sparse graphs and adjacency matrix for dense scenarios when appropriate.
* Use union-find with Kruskal for clear MST implementations.
* Validate edge cases: disconnected graphs, multiple components, isolated nodes.
* For multiple shortest-path queries on static graph with negative edges but no negative cycles, use Johnson’s algorithm (re-weight edges via Bellman–Ford then run Dijkstra from each node).

---

## ⚠️ Common Pitfalls

* Forgetting to check negative cycles with Bellman–Ford.
* Using Dijkstra on graphs with negative edges (incorrect results).
* Not using path compression or union by rank in DSU (slow in worst-case).
* Off-by-one or indexing errors in edge lists and graph creation.
