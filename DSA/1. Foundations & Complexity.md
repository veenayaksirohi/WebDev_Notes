## 📝 Overview

Understanding algorithm complexity and foundational concepts is crucial for analyzing and designing efficient solutions. This chapter covers Big O notation, time/space complexity, and recursion fundamentals — the building blocks for all DSA topics.

---

## 🧩 Core Concepts

### What is an Algorithm?

A **step-by-step procedure** to solve a problem or perform a computation. Algorithms must be:

- **Finite**: Terminates after finite steps
- **Definite**: Each step clearly defined
- **Input**: Zero or more inputs
- **Output**: At least one output
- **Effective**: Feasible to execute

### What is a Data Structure?

A way to **organize and store data** for efficient access and modification. Examples: arrays, linked lists, trees, graphs.

### Problem Types

- **Search**: Finding elements (linear search, binary search)
- **Sort**: Ordering elements (merge sort, quick sort)
- **Optimization**: Finding best solution (shortest path, minimum cost)
- **Decision**: Yes/no answers (is graph connected?)

## 📊 Complexity Analysis

### Big O Notation (O)

**Upper bound** — describes worst-case scenario.

- Represents maximum time/space an algorithm will take
- Ignores constants and lower-order terms
- Example: `O(2n + 5)` → `O(n)`

### Big Omega (Ω)

**Lower bound** — describes best-case scenario.

### Big Theta (Θ)

**Tight bound** — describes average case when upper and lower bounds match.

### Common Complexities (Best to Worst)

| Notation   | Name         | Example                         |
| ---------- | ------------ | ------------------------------- |
| O(1)       | Constant     | Array access, hash table lookup |
| O(log n)   | Logarithmic  | Binary search                   |
| O(n)       | Linear       | Linear search, array traversal  |
| O(n log n) | Linearithmic | Merge sort, heap sort           |
| O(n²)      | Quadratic    | Bubble sort, nested loops       |
| O(n³)      | Cubic        | Floyd-Warshall                  |
| O(2ⁿ)      | Exponential  | Recursive Fibonacci (naive)     |
| O(n!)      | Factorial    | Permutations generation         |

### Growth Comparison

For n = 1000:

- O(1) = 1 operation
- O(log n) ≈ 10 operations
- O(n) = 1,000 operations
- O(n log n) ≈ 10,000 operations
- O(n²) = 1,000,000 operations
- O(2ⁿ) = 10³⁰⁰ operations (infeasible!)

## ⏱️ Time & Space Complexity

### Time Complexity

Measures how **execution time grows** with input size.

**Example — Linear search**

```python
def linear_search(arr, target):
    for i in range(len(arr)):  # O(n) iterations
        if arr[i] == target:
            return i
    return -1
# Time: O(n), Space: O(1)
```

### Space Complexity

Measures **memory usage growth** with input size.

- **Auxiliary space**: Extra space used (excluding input)
- **Total space**: Input + auxiliary space

**Example — Recursive factorial**

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)
# Time: O(n), Space: O(n) due to call stack
```

### Best, Average, Worst Case

- **Best case**: Minimum operations needed (e.g., target at first position)
- **Average case**: Expected operations over all inputs
- **Worst case**: Maximum operations needed (e.g., target not found)

**Example — Quick Sort**

- Best/Average: O(n log n)
- Worst: O(n²) when pivot is always smallest/largest

## 🔄 Recursion Basics

### Components of Recursion

1. **Base case**: Condition to stop recursion
2. **Recursive case**: Function calling itself with modified input
3. **Progress**: Each call moves toward base case

### Call Stack

Function calls stored in **stack memory**:

- Each call creates a new stack frame
- Frames popped when function returns
- Stack overflow if too many recursive calls

### Example — Fibonacci

**Naive recursive (exponential)**

```python
def fib(n):
    if n <= 1:  # Base case
        return n
    return fib(n-1) + fib(n-2)  # Recursive case
# Time: O(2ⁿ), Space: O(n) call stack
```

**Optimized with memoization**

```python
def fib(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib(n-1, memo) + fib(n-2, memo)
    return memo[n]
# Time: O(n), Space: O(n)
```

### Recurrence Relations

Express time complexity recursively:

- **T(n) = T(n-1) + O(1)** → O(n) (linear recursion)
- **T(n) = 2T(n/2) + O(n)** → O(n log n) (divide & conquer)
- **T(n) = T(n-1) + T(n-2) + O(1)** → O(2ⁿ) (Fibonacci)

Use **Master Theorem** for divide-and-conquer recurrences.

## ✅ Best Practices

- Always analyze **both time and space** complexity
- Consider **best, average, and worst** cases
- Use **Big O for upper bound** analysis in interviews
- Understand **recursion depth** and stack overflow risks
- **Optimize space** when possible (iterative vs recursive)
- **Profile real code** — Big O is asymptotic, not absolute

---

## ⚠️ Common Pitfalls

- Confusing O(n) with O(n²) in nested loops
- Ignoring space complexity (especially recursion stack)
- Assuming O(1) for operations that aren't (e.g., string concatenation in loops)
- Not considering average case (e.g., hash table collisions)
- Stack overflow from deep recursion without tail-call optimization

## 🔍 Interview Questions

| #   | Question                                         | Key Points to Cover                                    |
| --- | ------------------------------------------------ | ------------------------------------------------------ |
| 1   | What is Big O notation?                          | Upper bound, worst case, ignores constants             |
| 2   | Difference between O(n) and O(n²)?               | Linear vs quadratic growth; nested loops               |
| 3   | What is space complexity?                        | Memory usage analysis; stack space for recursion       |
| 4   | How does recursion work?                         | Call stack, base case, recursive case, stack frames    |
| 5   | What is the complexity of binary search?         | O(log n) — halves search space each iteration          |
| 6   | Why is naive Fibonacci O(2ⁿ)?                    | Each call spawns 2 more; exponential tree growth       |
| 7   | How to optimize recursive solutions?             | Memoization (top-down DP) or tabulation (bottom-up DP) |
| 8   | What's the difference between O(log n) and O(n)? | Logarithmic grows much slower; binary search vs linear |

### Interview Tip

When explaining complexity:

1. State the **time and space** complexity
2. Explain **why** (loop iterations, recursion depth)
3. Mention **best/worst case** if relevant
4. Compare to alternative approaches
