## 🌲 Tries (Prefix Trees)

### Structure & use-cases

* A **trie** stores strings in a tree where each edge represents a character. Useful for autocomplete, prefix queries, dictionary lookups, and word-search puzzles.
* Each node typically contains: children map/array, `is_word` flag, and optionally a `count` for prefix frequency.

**Complexity:** Insert/search `O(L)` where `L` is string length. Space can be large (`O(sum of lengths)`), can be improved with compressed tries (radix/trie/DAWG).

### Insert / Search / Prefix count examples (Python sketch)

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False
        self.count = 0  # number of words through this node

class Trie:
    def __init__(self): self.root = TrieNode()
    def insert(self, word):
        node = self.root; node.count += 1
        for ch in word:
            node = node.children.setdefault(ch, TrieNode()); node.count += 1
        node.is_word = True
    def search(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children: return False
            node = node.children[ch]
        return node.is_word
    def starts_with(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children: return 0
            node = node.children[ch]
        return node.count
```

**Interview tips:** mention trade-offs vs hash maps, and discuss memory-reduced variants (ternary search tries, compressed/radix trie).

## 🔤 String Algorithms

### KMP (Knuth–Morris–Pratt)

* Builds a **prefix function** (pi) that for each position gives the length of the longest proper prefix that is also a suffix ending at that position.
* Use pi to skip characters when mismatch occurs → overall `O(n + m)` for pattern search.

**Prefix function (pi) sketch**

```python
def prefix_function(s):
    n = len(s); pi = [0]*n
    for i in range(1, n):
        j = pi[i-1]
        while j>0 and s[i]!=s[j]: j = pi[j-1]
        if s[i]==s[j]: j += 1
        pi[i] = j
    return pi
```

**Use:** pattern search via `pattern + '#' + text` or direct streaming match.

### Z-function

* `Z[i]` = length of longest substring starting at `i` that matches prefix of string.
* Also computed in `O(n)` and useful for pattern matching, finding periodicity, and string comparisons.

**Z-function sketch**

```python
def z_function(s):
    n = len(s); z = [0]*n
    l = r = 0
    for i in range(1, n):
        if i <= r: z[i] = min(r-i+1, z[i-l])
        while i+z[i] < n and s[z[i]] == s[i+z[i]]: z[i] += 1
        if i+z[i]-1 > r: l, r = i, i+z[i]-1
    return z
```

### Rabin–Karp (rolling hash)

* Compute rolling hash of length-`m` substrings and compare with pattern hash; use double-check on collisions.
* Average `O(n)` but beware collisions; use two moduli or 64-bit rolling hash.

**Rolling hash idea:** `hash_{i+1} = (hash_i - s[i]*p^{m-1})*p + s[i+m] (mod M)`

### When to use which

* **KMP/Z** for guaranteed `O(n+m)` pattern matching with no hashing overhead.
* **Rabin–Karp** when searching many patterns of same length (multi-pattern) or easier rolling comparisons (but handle collisions).
* **Z-function** is elegant for palindrome periodicity, occurrences count, smallest cyclic shift problems.

## 🧰 Advanced Data Structures

### Segment Trees (range queries & updates)

* Segment tree stores aggregates (sum/min/max/gcd) for intervals; supports `O(log n)` range query and `O(log n)` updates.
* Variants: lazy propagation (range updates), persistent segment trees, segment tree on indices/values.

**Build / query / update sketch**

```python
# 1-based tree array of size 4*n
def build(node,l,r):
    if l==r: tree[node] = arr[l]; return
    mid=(l+r)//2; build(node*2,l,mid); build(node*2+1,mid+1,r)
    tree[node]=tree[node*2]+tree[node*2+1]

def query(node,l,r,ql,qr):
    if qr<l or r<ql: return 0
    if ql<=l and r<=qr: return tree[node]
    mid=(l+r)//2
    return query(node*2,l,mid,ql,qr)+query(node*2+1,mid+1,r,ql,qr)

def update(node,l,r,idx,val):
    if l==r: tree[node]=val; return
    mid=(l+r)//2
    if idx<=mid: update(node*2,l,mid,idx,val)
    else: update(node*2+1,mid+1,r,idx,val)
    tree[node]=tree[node*2]+tree[node*2+1]
```

**Lazy propagation**: store pending updates at nodes to support range updates efficiently.

### Fenwick Tree / BIT (Binary Indexed Tree)

* Supports point update and prefix-sum query in `O(log n)` with `O(n)` space. Simpler & smaller constant than segment tree for prefix-based queries.

**Fenwick sketch (1-based)**

```python
def add(i,delta):
    while i<=n:
        bit[i]+=delta; i+= i&-i

def sum(i):
    res=0
    while i>0:
        res+=bit[i]; i-= i&-i
    return res
```

### Comparison & use-cases

* Use BIT for prefix sums & point updates, or when you need k-th order-statistics by binary-search on prefix sums.
* Use segment tree when you need range updates (without heavy tricks) or non-commutative merges or more complex queries.

## 🧭 Interview Prep & Patterns

* **Patterns to master:** prefix-sum & difference arrays, sliding-window, two-pointers, trie-based dictionary problems, KMP for pattern matching, segment tree/BIT for range-query problems.
* **Practice strategy:** solve 3–5 problems per pattern; alternate between implementation and problem solving; time yourself for mock interviews.
* **Problem sources:** LeetCode (Top Interview Questions lists), Codeforces (for speed & tricky edge-cases), AtCoder (strict limits), HackerRank/InterviewBit for structured tracks.
* **Contest practice:** short contests (30–90 mins) to build speed; read editorials afterward and reimplement cleaner solutions.

---

## ✅ Best Practices

* Explain your data structure choice and complexity trade-offs during interviews.
* For string matching, mention edge cases and prove correctness / collision handling for hashing.
* For segment trees and BIT, sketch index math and 1-based vs 0-based differences.
* Keep implementations modular: separate build/query/update functions.

---

## ⚠️ Common Pitfalls

* Off-by-one errors in BIT (1-based indexing) or segment tree ranges.
* Not handling hash collisions in Rabin–Karp (always verify match with direct compare or use double hash).
* Memory blow-up with naive tries — mention compressed variants.
* Forgetting to propagate lazy values in segment tree (getting wrong results in range updates).
