## 📝 Overview

Graphs model relationships between entities and are used across recommendation systems, routing, dependency resolution, social networks, and more. Understanding representations, traversal patterns, and core graph algorithms is essential for interviews and system design problems.

---

## 📐 Graph Modeling

### Directed vs Undirected

* **Directed graph (digraph):** edges have direction `u -> v` (e.g., webpage links, task dependencies).
* **Undirected graph:** edges are two-way `u -- v` (e.g., friendship, undirected road).

### Weighted vs Unweighted

* **Weighted graph:** edges carry weights/costs (e.g., distances, time).
* **Unweighted graph:** edges are equal-cost; BFS gives shortest path in edge count.

### Common real-world examples

* Social networks: undirected (friendship) or directed (follow)
* Maps/routing: weighted, directed or undirected
* Build systems: directed acyclic graph of dependencies
* Recommendations: bipartite graphs (users↔items)

## 🔢 Representations

### Adjacency list

* For each node, store list of neighbors (and weights). Typical representation for sparse graphs.

```python
# python adjacency list (unweighted)
graph = {
  0: [1, 2],
  1: [0, 3],
  2: [0],
  3: [1]
}
```

**Space:** `O(V + E)`

### Adjacency matrix

* `V x V` matrix `mat[u][v] = weight or 1/0`.

**Space:** `O(V^2)` — good for dense graphs or constant-time edge checks.

### Edge list

* List of edges `(u, v, w)` — useful for algorithms like Kruskal.

**Space:** `O(E)`

### When to use which representation

* Use adjacency list for most algorithmic problems (sparse graphs).
* Use adjacency matrix for dense graphs or small `V` where constant-time edge existence matters.
* Use edge list for sorting edges (Kruskal) or streaming edges.

## 🔎 Traversals: BFS & DFS

### Breadth-First Search (BFS)

* Explores in layers from a start node; uses a queue.
* Finds shortest path in unweighted graphs (fewest edges).

**BFS template (unweighted shortest path)**

```python
from collections import deque

def bfs_shortest_path(graph, start, target):
    q = deque([start])
    dist = {start: 0}
    parent = {start: None}
    while q:
        u = q.popleft()
        if u == target: break
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)
    return dist.get(target, -1)
```

**Complexity:** `O(V + E)`

### Depth-First Search (DFS)

* Explores as deep as possible along a branch; uses recursion or stack.
* Useful for topological sort (DFS post-order), cycle detection, connectivity.

**Recursive DFS**

```python
def dfs(u):
    visited.add(u)
    for v in graph[u]:
        if v not in visited:
            dfs(v)
```

**Complexity:** `O(V + E)`

### Connected components & bipartiteness via BFS/DFS

* For undirected graphs, run BFS/DFS from each unvisited node to find connected components.
* Check bipartiteness using 2-coloring with BFS/DFS — if conflict arises, not bipartite.

## ⚙️ Core Algorithms

### Topological sort (Kahn’s algorithm + DFS)

**Kahn’s (BFS-based)**

* Compute indegree for each node.
* Enqueue nodes with indegree 0; repeatedly pop and decrement neighbors’ indegree.
* If you output all nodes, graph is DAG; otherwise graph has cycle.

```python
from collections import deque

def topo_kahn(graph, V):
    indeg = [0]*V
    for u in graph:
        for v in graph[u]: indeg[v] += 1
    q = deque([u for u in range(V) if indeg[u] == 0])
    order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in graph.get(u, []):
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    if len(order) != V: return None  # cycle
    return order
```

**DFS-based topological sort** uses reverse of post-order.

### Cycle detection (directed & undirected)

* **Directed:** use DFS with a recursion stack (colors: white/gray/black). If you meet a gray node, there's a back-edge → cycle.
* **Undirected:** during DFS, if you meet a visited node that is not the parent → cycle.

**Directed cycle detect (colors)**

```python
def has_cycle_dfs(u):
    color[u] = 1  # gray
    for v in graph[u]:
        if color[v] == 0 and has_cycle_dfs(v): return True
        if color[v] == 1: return True
    color[u] = 2
    return False
```

### Bipartite check (2-coloring)

* BFS/DFS color nodes alternately. If neighbor has same color → not bipartite.

```python
from collections import deque

def is_bipartite(graph, V):
    color = [None]*V
    for s in range(V):
        if color[s] is None:
            color[s] = 0
            q = deque([s])
            while q:
                u = q.popleft()
                for v in graph[u]:
                    if color[v] is None:
                        color[v] = 1 - color[u]
                        q.append(v)
                    elif color[v] == color[u]:
                        return False
    return True
```

### Shortest paths (overview)

* **Unweighted:** BFS
* **Weighted (non-negative):** Dijkstra (`O((V+E) log V)` with heap)
* **All-pairs:** Floyd-Warshall `O(V^3)` or repeated Dijkstra
* **Negative edges:** Bellman-Ford (`O(VE)`) detects negative cycles

---

## 🧾 Complexity Summary

* Traversals (BFS/DFS): `O(V + E)`
* Topological sort (Kahn/DFS): `O(V + E)`
* Cycle detection: `O(V + E)`
* Dijkstra (with binary heap): `O((V + E) log V)`
* Bellman-Ford: `O(V * E)`

---

## ✅ Best Practices

* Choose adjacency list for algorithmic problems unless dense graph.
* Be explicit about directed vs undirected and 0-based vs 1-based node indexing in answers.
* For repeated shortest-path queries on static graphs, consider preprocessing (e.g., APSP, Johnson’s algorithm).
* Use visited sets/arrays to avoid revisiting nodes.

---

## ⚠️ Common Pitfalls

* Forgetting to clear or reinitialize visited/state between runs
* Mixing up parent check in undirected cycle detection (false positive)
* Using adjacency matrix for large sparse graphs (memory blowup)
* Off-by-one node indexing mismatches during implementation
