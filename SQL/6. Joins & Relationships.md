## 📝 Overview

SQL **JOINs** combine rows from multiple tables based on related columns. They are essential for querying normalized data in real systems.

---

## 📋 Example Tables

**Employees**

| id  | name  | dept_id | manager_id |
| --- | ----- | ------- | ---------- |
| 1   | Amit  | 10      | NULL       |
| 2   | Neha  | 20      | 1          |
| 3   | Rahul | 10      | 1          |
| 4   | Sana  | NULL    | 2          |

**Departments**

| dept_id | dept_name   |
| ------- | ----------- |

## 🔵 INNER JOIN

Returns **matching rows only**.

### Query

```sql
SELECT e.id, e.name, d.dept_name
FROM employees e
INNER JOIN departments d
  ON e.dept_id = d.dept_id;
```

### Result

| id  | name  | dept_name   |
| --- | ----- | ----------- |
| 1   | Amit  | Engineering |
| 2   | Neha  | HR          |
| 3   | Rahul | Engineering |

---

## ⬅️ LEFT JOIN

Returns all rows from left table **plus matching right**.

### Query

```sql
SELECT e.id, e.name, d.dept_name
FROM employees e
LEFT JOIN departments d
  ON e.dept_id = d.dept_id;
```

### Result

| id  | name  | dept_name   |
| --- | ----- | ----------- |
| 1   | Amit  | Engineering |
| 2   | Neha  | HR          |
| 3   | Rahul | Engineering |
| 4   | Sana  | NULL        |

---

## ➡️ RIGHT JOIN

All rows from right table **plus matching left**.

### Query

```sql
SELECT e.id, e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d
  ON e.dept_id = d.dept_id;
```

### Result

| id   | name  | dept_name   |
| ---- | ----- | ----------- |
| 1    | Amit  | Engineering |
| 2    | Neha  | HR          |
| 3    | Rahul | Engineering |
| NULL | NULL  | Marketing   |

---

## 🌐 FULL OUTER JOIN

All rows from both tables; unmatched get NULL.

### Simulated in MySQL/PostgreSQL

```sql
SELECT e.id, e.name, d.dept_name
FROM employees e
LEFT JOIN departments d
  ON e.dept_id = d.dept_id
UNION
SELECT e.id, e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d
  ON e.dept_id = d.dept_id;
```

### Result

| id   | name  | dept_name   |
| ---- | ----- | ----------- |
| 1    | Amit  | Engineering |
| 2    | Neha  | HR          |
| 3    | Rahul | Engineering |
| 4    | Sana  | NULL        |
| NULL | NULL  | Marketing   |

---

## 🔁 Self Join

Table joined to itself (e.g., employee → manager).

### Query

```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.id;
```

### Result

| employee | manager |
| -------- | ------- |
| Amit     | NULL    |
| Neha     | Amit    |
| Rahul    | Amit    |
| Sana     | Neha    |

---

## ❌ Cross Join

Cartesian product: all combinations.

### Query

```sql
SELECT e.name AS employee, d.dept_name
FROM employees e
CROSS JOIN departments d;
```

Partial Result:

| employee | dept_name   |
| -------- | ----------- |
| Amit     | Engineering |
| Amit     | HR          |
| Amit     | Marketing   |
| …        | …           |

---

## 📊 Join Comparison Summary

| Join Type       | Returns                      |
| --------------- | ---------------------------- |
| INNER JOIN      | Matching rows only           |
| LEFT JOIN       | All left + matches           |
| RIGHT JOIN      | All right + matches          |
| FULL OUTER JOIN | All rows from both tables    |
| SELF JOIN       | Table joined with itself     |
| CROSS JOIN      | Cartesian product            |

| #   | Question                              | Key Points                          |
| --- | ------------------------------------- | ----------------------------------- |
| 1   | What is INNER JOIN?                   | Returns only matching rows          |
