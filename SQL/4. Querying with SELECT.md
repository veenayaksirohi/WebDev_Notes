## 📝 Overview

The `SELECT` statement is used to **retrieve data** from one or more tables. It is the **most frequently used SQL command** and forms the foundation of querying.

A `SELECT` query can:

- Choose specific columns
    
- Remove duplicates
    
- Filter rows
    
- Sort results
    
- Limit returned records
    

---

## 📌 Basic SELECT

### Select All Columns

```sql
SELECT * FROM employees;
```

### Select Specific Columns

```sql
SELECT id, name, salary
FROM employees;
```

### Column Aliases (AS)

Used to rename columns in output.

```sql
SELECT name AS employee_name,
       salary AS monthly_salary
FROM employees;
```

> `AS` is optional but improves readability.

### DISTINCT

Removes duplicate values.

```sql
SELECT DISTINCT department
FROM employees;
```

---

## 🔎 Filtering with WHERE

Used to **filter rows** based on conditions.

### Basic WHERE

```sql
SELECT *
FROM employees
WHERE salary > 50000;
```

### Using Operators

```sql
SELECT *
FROM employees
WHERE salary BETWEEN 40000 AND 70000;
```

```sql
SELECT *
FROM employees
WHERE department IN ('HR', 'IT');
```

```sql
SELECT *
FROM employees
WHERE name LIKE 'A%';
```

---

## 🔃 Sorting with ORDER BY

Used to **sort query results**.

### Ascending Order (Default)

```sql
SELECT name, salary
FROM employees
ORDER BY salary ASC;
```

### Descending Order

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

### Multiple Columns Sorting

```sql
SELECT *
FROM employees
ORDER BY department ASC, salary DESC;
```

---

## 📏 Limiting Results

Used to restrict the number of rows returned.

### LIMIT (MySQL / PostgreSQL)

```sql
SELECT *
FROM employees
LIMIT 5;
```

### LIMIT with OFFSET

```sql
SELECT *
FROM employees
LIMIT 5 OFFSET 10;
```

> Used for pagination.

### TOP (SQL Server)

```sql
SELECT TOP 5 *
FROM employees;
```

---

## ✅ Best Practices

- Avoid `SELECT *` in production
    
- Always use `ORDER BY` with `LIMIT`
    
- Use aliases for clarity
    
- Filter early using `WHERE` for performance
    

---

## ⚠️ Common Pitfalls

- Forgetting `ORDER BY` with `LIMIT`
    
- Confusing `WHERE` and `HAVING`
    
- Using `LIKE '%text%'` on large tables (slow)
    
- Assuming default order without sorting
