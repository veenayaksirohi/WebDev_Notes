## 📝 Overview

**Subqueries** (nested queries) are queries inside other queries. They can return a single scalar value, a row, a column, or a result set. **Set operations** combine results from multiple queries into a single result.

Use cases: conditional filtering, existence checks, de-duplication, and combining datasets.

## 🔢 Scalar Subqueries

Return a **single value** (one row, one column). Often used in `WHERE`, `SELECT`, or `HAVING`.

**Example — highest salary employee(s)**

```sql
SELECT name
FROM employees
WHERE salary = (SELECT MAX(salary) FROM employees);
```

**Explanation:** The inner query returns one value (`MAX(salary)`), used by the outer query.

---

## 🔁 Correlated Subqueries

A correlated subquery **depends on the outer query**. It is evaluated once per outer row.

**Example — employees earning above their department average**

```sql
SELECT e.id, e.name, e.salary
FROM employees e
WHERE e.salary > (
  SELECT AVG(salary)
  FROM employees x
  WHERE x.dept_id = e.dept_id
);
```

**Explanation:** The inner query references `e.dept_id` from the outer query — it runs per employee.

## ✅ EXISTS / NOT EXISTS

Efficient way to test **existence** of rows returned by a subquery (stops at first match).

**Example — departments that have employees**

```sql
SELECT d.dept_name
FROM departments d
WHERE EXISTS (
  SELECT 1
  FROM employees e
  WHERE e.dept_id = d.dept_id
);
```

**NOT EXISTS example — departments with no employees**

```sql
SELECT d.dept_name
FROM departments d
WHERE NOT EXISTS (
  SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id
);
```

## 🔗 Set Operations: UNION / INTERSECT / EXCEPT

Combine **entire result sets** (columns must be compatible).

### UNION vs UNION ALL

- `UNION` removes duplicates
    
- `UNION ALL` preserves duplicates and is faster
    

**Example — unique customer names from orders and employees table**

```sql
SELECT name AS person
FROM employees
UNION
SELECT customer AS person
FROM orders;
```

### INTERSECT

Returns rows present in **both** queries (not supported in MySQL; supported in PostgreSQL/SQL Server).

**Example**

```sql
SELECT name FROM employees
INTERSECT
SELECT customer FROM orders;
```

### EXCEPT / MINUS

Returns rows from first query **not in** second (Postgres uses `EXCEPT`, Oracle uses `MINUS`).

**Example**

```sql
SELECT name FROM employees
EXCEPT
SELECT customer FROM orders;
```

---

## ✅ Best Practices

- Use `EXISTS` for existence checks (often more efficient than `IN` with subqueries)
    
- Prefer `UNION ALL` when duplicates are acceptable to avoid the sorting/dedup cost
    
- Prefer joins for simple relational retrievals; use subqueries when logic requires them
    
- For correlated subqueries, consider re-writing with joins or window functions if performance is an issue
    

---

## ⚠️ Common Pitfalls

- Assuming `IN (subquery)` behaves like `EXISTS` in performance — differs by DB and optimizer
    
- Using scalar subquery that returns multiple rows (causes error)
    
- Mismatched column types or column counts in set operations
    
- Forgetting `UNION` removes duplicates (unexpected row reductions)
