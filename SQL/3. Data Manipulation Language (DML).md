## 📝 Overview

**DML (Data Manipulation Language)** is a subset of SQL used to **insert, update, delete, and manage data** stored inside database tables.

Unlike DDL, DML commands **operate on data**, not the structure.

**Key DML Commands:**

- `INSERT`
- `UPDATE`
- `DELETE`
- `MERGE` / `UPSERT`

> 🔁 DML commands are usually **transactional** and can be rolled back.

---

## ➕ INSERT

Used to **add new rows** into a table.

### Insert Single Row

```sql
INSERT INTO employees (id, name, salary)
VALUES (1, 'Amit', 50000);
```

### Insert Multiple Rows

```sql
INSERT INTO employees (id, name, salary)
VALUES
  (2, 'Neha', 60000),
  (3, 'Rahul', 55000);
```

### Insert with Selected Columns

```sql
INSERT INTO employees (name, salary)
VALUES ('Karan', 45000);
```

---

## ✏️ UPDATE

Used to **modify existing records**.

### Update Specific Rows

```sql
UPDATE employees
SET salary = 65000
WHERE id = 2;
```

### Update Multiple Columns

```sql
UPDATE employees
SET salary = 70000, name = 'Neha Sharma'
WHERE id = 2;
```

> ⚠️ Without `WHERE`, **all rows** will be updated.

---

## 🗑️ DELETE

Used to **remove rows** from a table.

### Delete Specific Rows

```sql
DELETE FROM employees
WHERE id = 3;
```

### Delete All Rows

```sql
DELETE FROM employees;
```

### DELETE vs TRUNCATE

| DELETE             | TRUNCATE              |
| ------------------ | --------------------- |
| Row-level deletion | Removes all rows      |
| Can be rolled back | Cannot be rolled back |
| Slower             | Faster                |

## 🔁 MERGE / UPSERT

Used to **insert or update data** depending on whether a record exists.

### MERGE (Standard SQL / Oracle / SQL Server)

```sql
MERGE INTO employees e
USING new_employees n
ON e.id = n.id
WHEN MATCHED THEN
  UPDATE SET e.salary = n.salary
WHEN NOT MATCHED THEN
  INSERT (id, name, salary)
  VALUES (n.id, n.name, n.salary);
```

### UPSERT (MySQL / PostgreSQL)

#### MySQL

```sql
INSERT INTO employees (id, name, salary)
VALUES (1, 'Amit', 55000)
ON DUPLICATE KEY UPDATE
salary = VALUES(salary);
```

#### PostgreSQL

```sql
INSERT INTO employees (id, name, salary)
VALUES (1, 'Amit', 55000)
ON CONFLICT (id)
DO UPDATE SET salary = EXCLUDED.salary;
```

## ✅ Best Practices

- Always use `WHERE` with `UPDATE` and `DELETE`
- Use transactions for critical updates
- Validate data before inserting
- Prefer `UPSERT` for idempotent operations

---

## ⚠️ Common Pitfalls

- Updating/deleting all rows accidentally
- Forgetting transaction handling
- Ignoring constraint violations
- Database-specific UPSERT syntax
