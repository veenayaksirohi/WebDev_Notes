SQL provides **aggregate functions** to compute summaries over rows, and **window functions** to compute values across a window of rows without reducing rows (unlike GROUP BY). These are essential for analytical queries.

---

## 📌 Aggregate Functions

Aggregate functions operate on a set of rows and return a **single value per group**. They are usually used with **GROUP BY**.

### COUNT

- `COUNT(*)`: Counts all rows
- `COUNT(column)`: Counts non-NULL values
- `COUNT(DISTINCT column)`: Counts unique non-NULL values

```sql
SELECT COUNT(*) AS total_employees FROM employees;
```

### SUM

Returns the **sum** of numeric values.

```sql
SELECT SUM(salary) AS total_salary FROM employees;
```

### AVG

Calculates the **average** of values.

```sql
SELECT AVG(salary) AS avg_salary FROM employees;
```

### MIN & MAX

Find the **minimum** and **maximum** respectively.

```sql
SELECT MIN(salary) AS lowest_salary, MAX(salary) AS highest_salary
FROM employees;
```

---

## 📂 GROUP BY

`GROUP BY` groups rows that have the same values in specified columns so that aggregates can be computed per group.

```sql
SELECT dept_id, COUNT(*) AS emp_count
FROM employees
GROUP BY dept_id;
```

Multiple aggregates on group:

```sql
SELECT dept_id,
       COUNT(*) AS total_emp,
       AVG(salary) AS avg_salary,
       MAX(salary) AS max_salary
FROM employees
GROUP BY dept_id;
```

➡ Columns in the `SELECT` that are not aggregates must appear in `GROUP BY`.

---

## 🔎 HAVING

The `HAVING` clause filters **groups** after aggregation (WHERE filters before grouping).

```sql
SELECT dept_id, COUNT(*) AS emp_count
FROM employees
GROUP BY dept_id
HAVING COUNT(*) > 5;
```

## 📈 Window Functions

Window functions compute values over a "window" of rows **without collapsing** them into groups. Use the `OVER()` clause with optional `PARTITION BY` and `ORDER BY`.

### ROW_NUMBER, RANK

- `ROW_NUMBER()`: Unique row number within partition
- `RANK()`: Rank of rows with gaps for ties
- `DENSE_RANK()`: Rank without gaps

```sql
SELECT name,
       ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
FROM employees;
```

### PARTITION BY & ORDER BY

- `PARTITION BY`: Divides rows into partitions
- `ORDER BY`: Defines ordering within each partition

```sql
SELECT name,
       AVG(salary) OVER (PARTITION BY dept_id) AS dept_avg_salary
FROM employees;
```

Here the average salary is computed per department while **retaining all rows**.

## 🔍 Interview Questions

| #   | Question                                | Key Points                                                  |
| --- | --------------------------------------- | ----------------------------------------------------------- |
| 1   | What is an aggregate function?          | Returns summary per group (COUNT, SUM, AVG, MIN, MAX)       |
| 2   | Why do we use GROUP BY?                 | To group rows for aggregates                                |
| 3   | Difference between WHERE and HAVING?    | WHERE filters before grouping; HAVING filters after         |
| 4   | What is a window function?              | Analytic function over a set of rows with `OVER()`          |
| 5   | When to use ROW_NUMBER vs RANK?         | ROW_NUMBER gives unique per row; RANK preserves ties        |
