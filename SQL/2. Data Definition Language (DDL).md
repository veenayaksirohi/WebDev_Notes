## 📝 Overview

**DDL (Data Definition Language)** is a subset of SQL used to **define, modify, and remove database structures** such as databases, tables, and schemas.

DDL commands **change the structure**, not the data itself.

**Key DDL Commands:**

- `CREATE`
- `ALTER`
- `DROP`
- `RENAME`
- `TRUNCATE` (sometimes grouped with DDL)

> ⚠️ DDL operations are usually **auto-committed** and cannot be rolled back easily.

---

## 🏗️ CREATE DATABASE & TABLE

### Create Database

```sql
CREATE DATABASE company_db;
```

```sql
CREATE DATABASE IF NOT EXISTS company_db;
```

### Create Table

```sql
CREATE TABLE employees (
  id INT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(150) UNIQUE,
  salary DECIMAL(10,2),
  joining_date DATE
);
```

### Simple Explanation

- Defines **table structure**
- Specifies **columns and data types**
- Can apply **constraints** during creation

## 🛠️ ALTER TABLE

Used to **modify an existing table structure**.

### Add a Column

```sql
ALTER TABLE employees
ADD department VARCHAR(50);
```

### Modify a Column

```sql
ALTER TABLE employees
MODIFY salary DECIMAL(12,2);
```

### Rename a Column

```sql
ALTER TABLE employees
RENAME COLUMN name TO full_name;
```

### Drop a Column

```sql
ALTER TABLE employees
DROP COLUMN department;
```

> ⚠️ `MODIFY` / `RENAME COLUMN` syntax may vary slightly across databases.

## 🗑️ DROP & ✏️ RENAME

### DROP TABLE

```sql
DROP TABLE employees;
```

```sql
DROP TABLE IF EXISTS employees;
```

### RENAME TABLE

```sql
RENAME TABLE employees TO staff;
```

### Key Difference

| Command | Effect                        |
| ------- | ----------------------------- |
| DROP    | Permanently removes structure |
| RENAME  | Changes object name only      |

## 🔒 Constraints

Constraints enforce **rules on data** to maintain **data integrity**.

### NOT NULL

Prevents null values.

```sql
name VARCHAR(100) NOT NULL
```

### DEFAULT

Assigns a default value.

```sql
status VARCHAR(20) DEFAULT 'ACTIVE'
```

### CHECK

Restricts values based on condition.

```sql
age INT CHECK (age >= 18)
```

### Combined Example

```sql
CREATE TABLE users (
  id INT PRIMARY KEY,
  username VARCHAR(50) NOT NULL,
  age INT CHECK (age >= 18),
  is_active BOOLEAN DEFAULT TRUE
);
```

---

## ✅ Best Practices

- Use constraints to protect data
- Avoid frequent `ALTER TABLE` on large tables
- Use `IF EXISTS` / `IF NOT EXISTS`
- Follow consistent naming conventions
- Test DDL changes in staging first

## ⚠️ Common Pitfalls

- Dropping tables accidentally
- Forgetting constraints
- Assuming DDL is rollback-safe
- Database-specific syntax differences
